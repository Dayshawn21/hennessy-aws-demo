# Hennessy Williams Photo: AWS demo

A portfolio demo that hosts a React marketing site on AWS and saves contact-form inquiries to a database.
It is a **demo only**: placeholder images, fake data, no payments, no galleries. The photographer gave permission to use her business name and contact details. Her real photos are not in this repo.

Live demo: https://d3vxtn9s8u8bor.cloudfront.net

## Architecture

```
Browser -> CloudFront -> private S3 bucket (static React build, Origin Access Control)
Browser -> API Gateway (HTTP API: POST /inquiries, GET /slots, POST /bookings) -> Lambda (TypeScript) -> DynamoDB
Admin -> Cognito hosted login (PKCE) -> JWT authorizer on /admin/* routes -> admin Lambda -> DynamoDB
                                                         \-> CloudWatch Logs
```

| Piece | What it does |
|---|---|
| S3 (private) | Holds the Vite build. No public access; only CloudFront can read it. |
| CloudFront | Serves the site over HTTPS. 403/404 return `/index.html` (status 200) so client-side routes survive a refresh. |
| API Gateway (HTTP API) | `POST /inquiries`, `GET /slots`, `POST /bookings`, CORS limited to the CloudFront domain, throttled to 5 requests/second (burst 10). |
| Cognito | User pool with an `admin` group; hosted login. The site holds only the public domain and client ID. |
| Lambda (Node.js, TypeScript) | Three functions (the third, admin, is described under Status). `inquiries` validates the form and writes the item (role: `PutItem` only). `bookings` lists open slots and requests one (role: `Query`, `UpdateItem`, `PutItem` on one table). Each has its own role. |
| DynamoDB (on-demand) | One table with `pk` / `sk`. Inquiry: `INQ#<id>` / `META`. Slot: `SLOT#<date>` / `<time>`, status `open` or `requested`. Booking request: `REQ#<id>` / `META`. |
| CloudWatch Logs | Lambda logs. |

## Status

Done and working:
- Static hosting on S3 + CloudFront with Origin Access Control and SPA fallback
- Inquiry API: contact form -> API Gateway -> Lambda -> DynamoDB
- API throttling on the default stage (rate 5/s, burst 10)
- Booking requests with no double booking: one DynamoDB transaction flips a slot `open` -> `requested` only if it is still open, and records the request. Tested with parallel requests (`scripts/race-test.mjs`): exactly one 201, the rest 409.

Written but never run: a GitHub Actions deploy (`.github/workflows/deploy.yml`, GitHub OIDC, no stored keys). It cannot run on this AWS account: the account is on the AWS Free Plan, and a service control policy explicitly denies `iam:CreateOpenIDConnectProvider` (the console also locks IAM identity providers until the account is upgraded, which removes the spend limits). I chose not to upgrade, so deploys are manual.

- Admin login with Cognito (hosted UI, authorization code + PKCE, self-registration off, `admin` group). Admin routes `GET /admin/overview` and `POST /admin/requests/{id}/confirm|decline` sit behind an API Gateway JWT authorizer (signed-out calls return 401) and the Lambda also checks the `admin` group.
- `/admin` dashboard (React): requests and inquiries, confirm/decline, simple bar charts. Confirm and decline are conditional DynamoDB transactions. Checked live: confirm set a request to `booked`, decline set it to `declined` and the slot accepted a new booking again.

Not built yet (planned in `AWS_DEMO_PLAN.md`): CloudWatch alarm, notes field and a by-city chart on the dashboard.

The admin Lambda in the console is named `hennessy-demo-admi` (a typo I did not rename). Charts are plain CSS bars, not Chart.js. The admin page is TypeScript but has no type-check step.

The console steps I followed are in `PHASE1_RUNBOOK.md` to `PHASE4_RUNBOOK.md`.

## Run it locally

```bash
npm install
npm run dev        # http://localhost:5173, contact form simulates sending
npm run build      # output in dist/client
npm run test:sites
```

The form posts to the API only when `VITE_API_URL` is set at build time (see `.env.production`). Without it the form uses the original simulated submit.

Build the Lambda zip:

```bash
npm run build:api  # api/dist/inquiries.zip and api/dist/bookings.zip
```

Placeholder images are generated by `scripts/generate-placeholders.mjs`.

## Deploying (manual)

`.github/workflows/deploy.yml` and `PHASE5_RUNBOOK.md` describe the intended OIDC pipeline, but it has not been run (see Status). Until then:

1. `npm run build`
2. Upload `dist/client` to the S3 bucket (keep files under their folders, e.g. `assets/`).
3. Create a CloudFront invalidation for `/*`.

## Notes

- Frontend is Vite + React (JavaScript). The Lambda is TypeScript, bundled with esbuild.
- No AWS keys are stored in this repo. The API URL in `.env.production` is public.
- Delete the AWS resources when the demo is finished: CloudFront distribution (disable, then delete), S3 bucket (empty, then delete), Lambda, API, DynamoDB table, IAM role.
